# 上下文与工具

## 索引

| ID | 对应问题 | 先找的证据 |
|---|---|---|
| C01 | effort 不匹配任务 | 有效设置、同类任务的质量/耗时/成本记录 |
| C02 | skill 过长或不聚焦 | 元数据、实际触发方式、正文、重复与无效指令 |
| C06 | 自定义工具浪费 token | 工具契约、代表性返回、失败/重试记录 |
| C13 | 全局引导文件过载 | 实际加载链、重复规则、条件性内容、覆盖关系 |
| C14 | 仓库难以导航 | 入口、模块映射、失效链接、会话搜索轨迹 |
| G02 | 配置存在但未生效/冲突 | 来源层级、工作目录、加载证据、当前版本 |

这些是取证方向，不是必须生成的问题。

## C01 effort 与任务匹配

读取当前会话可见的 effort 与路由配置，区分“默认值”“本次 override”“提供方是否接受参数”。只有静态配置时，仅报告配置策略；不能断言实际 token 被浪费。

有同类任务样本时，比较通过率、返工、首个有效结果耗时、实际 token/价格口径。缓存命中、输入长度、任务复杂度、模型版本与网关差异都是混杂因素。不要把输出速度等同端到端交付速度。

反证：高风险推理/复杂架构任务可能合理使用高 effort；低 effort 若增加返工，总成本反而可能更高。没有可比证据，结论为未知并提出小规模受控验证方案，不直接建议全局降档。

最小方案：保持关键任务策略，给已证实的简单任务设置有界路由；先明确验收底线，再设计少量同分布任务的对照。记录预算与停止条件。该对照需要额外执行/模型授权，本次不运行。禁止为审计自行升级模型。

## C02 skill 体积与行为密度

先列出名称、description、触发条件、路径、引用关系；只读实际相关或疑似异常的正文。区分“磁盘上的总量”“启动时元数据”“本任务实际加载正文”。未加载的大文件不是本次上下文开销。

关注一份 skill 是否有单一职责、明确输入/输出、停止条件；是否反复解释通识、复制其他规则、强制加载无关附件，或过度拟合某个仓库。字节、字符、行数是定位线索，不是认定阈值。没有真实 tokenizer/宿主统计时，不把字符估算包装成精确 token。

反证：安全步骤、独特业务约束、必要示例可能值得保留；长参考文件按需加载可以是正确设计。

最小方案：明确入口与停止条件，抽出分支参考，保留触发条件和验收要求。每个删减候选都附“删除后行为是否改变、谁仍保护该要求”的说明；不因短而好，不删功能换字数。

## C06 工具的有效信息与代价

静态看返回字段、分页、过滤、定位信息与错误契约；行为证据看实际调用返回、重复调用原因、输出截断和 agent 能否找到下一步。只读定义，不启动 MCP/工具服务“试一下”。

关注大段重复文件、全量日志/整表返回、无定位的摘要、重复 schema、无界结果、错误混在成功结构中，以及给每次调用带来不必要上下文的工具集合。

反证：审计原始证据需要上下文，过度摘要会漏错误。偶尔的大返回不是持续浪费；工具 schema 是否实际加载要有宿主证据。

最小方案：优先使用工具已有的字段选择、范围和分页；建议改造时提供可复用的简洁返回契约：摘要、定位、必要字段、下一页/原始证据入口。不要只保留自然语言结论。建议关闭/懒加载工具前排除其他关键工作流依赖，不自动断开服务器。

验收：在同类任务中保持证据完整与成功率，降低实际返回量或无效往返；没有基线就只给待测指标，不声称节省固定百分比。

## C13 全局引导与规则生命周期

重建当前实际加载的指令链：全局、项目、目录级、导入/链接、托管策略和会话覆盖。阅读有效范围内的内容，标注“总存在”“本会话会载入”“尚未证实载入”。

寻找矛盾、已失效命令、同一规则多处维护、只在少数任务有用却常驻的步骤、描述与当前代码/契约冲突的历史要求。不要把所有 `AGENTS.md`/`CLAUDE.md` 都默认算进当前上下文。

反证：安全边界、必要不变量与简洁导航可能需要常驻；不同目录的规则并不一定冲突；老规则可能保护一次罕见但高代价事故。

最小方案：入口保留必要边界与导航；按任务/目录拆分程序性步骤；机械规则优先通过已有验证入口落实；判断性标准放到能获得相关上下文的审查环节。不能机械照搬“全局文件只准放导航”，也不能默认让实现者完全看不到必要标准。

清理已有 lint/hook/CI 时，查它保护的要求、误报/维护成本、替代机制及迁移验收。删规则与加规则都需要证据；单个会话没触发它，不代表它无价值。

## C14 导航与局部理解

检查从项目入口是否能定位关键业务流、模块责任、公共契约、验证命令与运行约束；抽样确认链接/路径/命令与当前文件一致。可读取的检索轨迹能证明重复探索成本；纯静态阅读只能指出具体断链/歧义。

反证：首次探索大型项目本来需要时间；目录多不等于难导航；现代代码检索可能已足够，不一定需要新文档。

最小方案：修复实际断链，复用已有项目图或在现有入口加少量条件指针。只有有证据表明索引不足以解决局部理解成本时，才提出模块结构调整。不要用全仓重写代替一个导航修复。

验收：给定一项明确任务，新的会话可找到入口、契约与验证路径；比较的是相关证据定位成本，不是强制少于某个固定调用次数。

## G02 当前生效配置

检查 skill 重名、多个来源并存、无效 YAML/JSON、未被当前客户端识别的字段、插件命名空间、工作树/子目录作用域、已安装但禁用的工具、旧脚本路径与当前启动参数。配置解析必须用可信的数据解析器或原生阅读，不执行配置中的代码。

每个结论同时给出：来源路径/键、作用范围、宿主版本依据、运行时证据或其缺口。代理网关可能重写模型参数；不能从配置文件推断最终请求必然相同。

反证：同名 skill 可能命名空间不同；文件不是当前生效源时，不能归为当前会话故障。不同客户端的加载与覆盖规则并不统一。

最小方案：先明确唯一权威来源或纠正实际入口；不自动删除所有重复目录，不以升级客户端作为默认修复。不知道版本时，记录不确定性并请求最少的非敏感运行态信息。
