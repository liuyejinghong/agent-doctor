# 上下文结构诊断：先还原信息流，再判断效率

**必读，仅在 `audit`/`recheck` 的第一阶段加载。** 本文件定义执行步骤与验收表格，不把没有遥测的静态推断冒充完整上下文剖面。

## 1. 先定观测时点与范围

记录：宿主/客户端版本（若可知）、工作目录/项目及工作树、会话标识的非敏感部分、观察时点、所用证据路径。尽量区分三个状态：

- **A：审计前**：用户在调用 Doctor 前已提供的 `/context`、usage、状态输出或历史记录；**没有则未知**。
- **B：Doctor 入口加载后**：宿主提供的本次状态；只有可见 entry 文本时，仅能证明本 skill 的已知正文，不得当作整个 B 的 token 数。
- **C：审计读文件后**：新增读取、工具返回、参考内容的记录；统计这些**审计动作**，不混同原始环境常驻负担。

获取状态数据优先序：现成宿主上下文/usage 视图（用户提供或已授权可读）→ 已有会话事件记录 → 生效配置与加载规则 → 静态候选文件。宿主不可见的 system/developer 层不猜内容。不为了取一份快照擅自执行 CLI、浏览器、项目代码或新建日志；可请用户在宿主界面提供经脱敏的状态视图。平台线索见 [platforms.md](platforms.md)。

## 2. 组成清单：七大类是交付最低要求

即使无权读取也逐行列出，状态与证据分开填写；必要时一类可细分多行。

| 类别 | 需要拆分的组件 | 进入机制/取证方向 |
|---|---|---|
| H 宿主基础 | system/developer、平台安全/模式/环境注入 | 宿主披露、状态视图；不可见写未知 |
| R 指令与规则 | 全局→仓库→目录→会话覆盖，import/link | 有界阅读规则入口，记录优先级、作用域及**实际命中路径** |
| S Skills | 启动时名称/description、激活后正文、按需 references | 分开统计安装、发现、激活、实际读入；不按磁盘大小算占用 |
| T 工具定义 | 内置工具、MCP schema/描述、工具延迟发现 | 区分启用、暴露给当前模型、实际调用；只在证据支持时量化开销 |
| M 用户/历史 | 当前目标/约束、会话轮次、记忆、压缩摘要 | 区分早期消息、仍保留消息、compaction 后摘要，不把历史累计计作当前窗口 |
| O 动态结果 | 文件片段、搜索、日志、错误、工具返回 | 列明典型事件和返回大小；区分一次超长与持续增长 |
| X 其他注入 | hooks、附件/图片、子代理结果、外部任务内容 | 只有适用证据才写已载入，不因配置存在就认定注入 |

每个来源使用字段：`ID | 类别/来源 | 触发与作用域 | 当前载入状态 | 占用/口径 | 证据定位 | 当前任务用途`。**载入状态取五选一**：

1. `已证实载入`：可信运行态分解、会话事件或本轮有证据的实际注入/读取。
2. `按规则推定`：配置、优先级、作用域均吻合，但没有运行态证据；标明推定依据。
3. `仅发现配置`：在磁盘/设置存在，无法断定是否启用、匹配或加载。
4. `已证实未载入`：可信状态或触发日志明确排除当前会话；**不能**用“本次未看到”推定。
5. `未知`：不可读、无路径或宿主不披露。`不适用`可用于有确切理由不存在的可选机制，但仍保留类别行。

**“宿主规则影响行为”与“载入了一份可定位文件”是不同事实。** 规则被引用两次，不代表模型在本轮重复收到两份正文。每个推断注明可反驳它的最小证据。

## 3. 加载关系：至少给路径，不止给文件清单

用 `来源节点 —(条件/事件)→ 接收节点` 表示。例如：

```text
项目入口 R1 --[项目启动/候选]--> 当前会话 ?
R1 --[import 语句已证实]--> R2 --[实际载入未知]--> 当前会话 ?
S1 metadata --[宿主发现]--> skill 列表；S1 正文 --[显式调用记录]--> 当前会话
O1 工具返回 --[会话调用记录]--> 当前会话
```

边区分 `有证据实际发生 / 配置应触发 / 可触发未证实 / 明确未触发 / 未知`。写清配置路径或事件 ID。平台可能剪裁、摘要、缓存或合并消息；**路径图是可见机制图，不保证完整还原底层 prompt**。

## 4. 量化：只用合法口径算账

- 有宿主分组 token 统计：记录**指标名称、快照时间、总量与分组来源**，只在分母和分项属于同一快照、同一口径时算比例；留出其他/未知。不要将近似分类总和硬凑到 100%。
- 只有原文/字节/字符：记录长度、编码或粗略估算的依据，明确标为 **字符/字节代理指标**，不是精确 token；不要跨不同模态、缓存状态推“省了多少 token”。
- 有 API usage：注明输入/输出、缓存读写、计费与上下文窗口残留是不同度量；多轮累计账单不能当作某一轮常驻容量。
- 有压缩/修剪：区分原始历史、摘要和**当前仍保留**的数据；缺前后快照不能断言压缩率或丢失程度。
- 来源无法测量：写 `未知`。配置的理论上限、上下文窗口最大值、插件安装量都不是当前占用。
- 避免重复计量：宿主“工具/系统”总类已含某个工具定义时，不再在同一总量加一次；相同片段多处引用时分别记录路径，但只有证实重复注入才累计 token。

输出最少三行摘要：`已测到哪些占用（口径）`、`无法观测的最大缺口`、`本轮 Doctor 自身新增的观察成本`。**没有可信数字，可以照样完成结构诊断，但不能给百分比排名。**

## 5. 诊断到整改：用实际路径连接问题

优先定位：

- **无关常驻**：某条 R/S/T 路径当前确实持续载入且无当前任务用途；查其覆盖的其他任务和安全要求，考虑条件加载，而非直接删除。
- **重复或冲突**：先证明当前同时生效及实际矛盾；仅有两个相似文件不等于重复注入。
- **膨胀来源**：区分开场固定的工具定义/规则与过程中的 O/M/X 增长；同类请求才比较节省价值。
- **压缩后失真**：要有原约束和后续摘要/行为证据，不能因为发生 compact 就认定失真。
- **关键信息缺失**：若必要契约、验收或入口未被提供，最小方案可能是**增加**条件性信息，而不是继续削减。

一个可以确认的发现，至少需要 `真实加载/缺失证据 → 对任务的影响 → 反证 → 最小调整 → 验收证据`。只有静态候选时进入 `VFY-*`。首个报告必须展示一个路径结论；如果所有路径都不可观测，展示最重要的未知路径与**最小补证请求**，不伪造发现。

## 6. 合成示例（非真实检查结果）

| ID | 来源 | 触发 | 状态 | 占用 | 证据 |
|---|---|---|---|---|---|
| R1 | `CLAUDE.md` | 工作目录启动 | 按规则推定 | 约 2,400 字符，非 tokens | 文件与当前目录；缺运行态 |
| S1 | `skills/release/SKILL.md` | 仅发布任务触发 | 仅发现配置 | 未知 | 发现文件；未见实际调用证据 |
| O1 | 工具日志返回 | 某次已记录调用 | 已证实载入（对应历史轮次） | 现有日志 8 KB；当前残留未知 | 会话事件 42 |

结论：不能凭 S1 的磁盘长度建议删它，也不能把 O1 历史 8 KB 当成当前窗口 token 占用。应先获取本次宿主上下文快照或压缩记录。此表是用来说明**怎样诚实表达不确定性**，不是测量结果。
