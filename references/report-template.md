# 体检报告模板

这是结构模板，不是对任何真实项目的检查结果。删除无关占位符，但不能删除覆盖缺口、证据限定或授权边界。

报告 ID/版本：<项目标识 + 时间 + 版本>
范围：<当前根目录、子系统、配置来源、历史范围；敏感路径脱敏>
快照：<revision/工作树/dirty 信息，未知就写未知>
宿主：<harness/版本/工具/权限边界>
模型与 effort：<配置 / 运行时观察 / 未核实提供方声明分别列出>
模式与重点：<audit/recheck；用户表述到 mode/focus 的映射；显式范围限制>
复查基线：<旧报告/原 ID/当前证据；缺失时说明，仅能核对什么>
读取预算：<E 取证次数/字符，I 内部规则次数/字符，合计；上限/实测或估算/自动注入/停止原因>

覆盖：22 项中，已证实问题 <n>；样本内未见问题 <n>；未知 <n>；不适用 <n>；未检查 <n>。
这些是“检查项状态”的数量，不等于根因去重后的整改卡片数量。

## 3. 每项证据与整改卡

### AD-<编号>：<标题>

- 所属检查：<Cxx/Gxx，可多个>；项目/模块：<分类>。
- 事实：<已观察到什么，与推断分开>。
- 证据：<文件/行/键/会话事件/运行记录/ref/时间>。
- 影响链：<哪些工作会受影响；哪些环节尚未核实>。
- 反证与边界：<实际检查过的替代解释；为何仍成立/应缩小范围>。
- 根因：<不是症状堆砌>。
- 优先级与置信度：<分别说明理由>。
- 最小方案：<要改的对象与具体行为，不执行>。
- 保留项：<不能丢掉的要求、检查、权限边界>。
- 替代/不做：<至少一个合理选择及后果>。
- 预计收益/成本：<有基线则引用，无则写待测；S/M/L 依据>。
- 依赖与顺序：<精确 ID；不要把等级当执行顺序>。
- 验收：<输入/命令或人工核验、预期结果、目标 ref、失败标准>。
- 副作用与回滚：<写入路径、缓存/产物、联网、服务/状态影响；恢复方法>。
- 批准范围：<可改文件、允许动作、费用/网络/生产禁区；禁止项>。
- 状态：待审批。静态建议不是已执行修复。

### VFY-<编号>：<待验证问题>

写已知线索、不能下结论的原因、所需最小证据、只读替代方法、额外执行的副作用与授权范围、结果将如何影响结论。不要在标题中把假设写成事故事实。
