# Agent Doctor

[English](README.md) | 简体中文

**给 coding agent 的工作环境做体检，找出反复返工的原因，排清先改什么。**

Agent 总是改错文件、在目录里兜圈子，工具输出挤满上下文，改完代码却说不清怎么验证？除了模型能力，指令、工具、配置和验证流程也值得检查。

Agent Doctor 是面向 **Claude Code、Codex 和 OpenCode** 的只读环境体检 Skill。**先还原上下文结构与加载路径，再检查工具、验证和工作流**；根据证据给出 P0–P3 整改看板。你决定改什么，独立执行阶段才动手。

## 第一份交付：上下文结构图，不是 22 项打勾

一次体检要回答：**模型实际接收了哪些指令、skills、工具定义、历史与工具返回？它们通过什么条件加载？哪个环节在膨胀、冲突，或缺了关键约束？**

| 组成 | 必须区分的状态 |
|---|---|
| 宿主指令与全局/项目/目录规则 | 当前实际生效、按规则推定、仅发现配置、未知 |
| Skills 和工具/MCP 定义 | 安装或启用 ≠ 本轮真正加载；元数据 ≠ 正文 ≠ 工具返回 |
| 历史/记忆/压缩摘要、文件读取、hooks/回传 | 开场占用与工作中增长；历史累计量与窗口残留量 |

报告先给 **来源清单、加载链、可测占用与无法观测的缺口**，再提出改动。没有宿主 token 遥测时，明确“未知”，不拿字符数充当 tokens，更不会凭安装的文件大小判断上下文浪费。Doctor 自己的读取成本也单独标出。方法见 [上下文结构诊断](references/context-map.md)。

## 你会得到什么

不是一句“建议优化提示词”，而是：哪里有问题、为什么成立、应该先改什么、哪些约束必须保留，以及怎样验收和回滚。

**以下仅为合成示例，不是对任何真实仓库的诊断结果：**

| 队列 | ID | 优先级 | 发现或待验证问题 | 下一步 |
|---|---|---|---|---|
| 已确认问题 | AD-001 | P1 | `scripts/check.sh:12` 的 `pytest \|\| true` 把失败退出码变为成功；远端门禁仍未知 | 修正该入口的退出码传播，保留现有检查；在隔离环境验证失败与成功样本 |
| 待验证假设 | VFY-001 | P2 | 默认使用高 effort，但没有同类任务的成本与质量对照 | 先收集可比证据，再判断是否值得调整，不直接全局降档 |

正式报告先提供上下文结构与观测边界，再提供环境快照、22 项覆盖状态、整改看板和逐项证据卡。每张卡写清反证、根因、最小方案、保留项、成本依据、依赖、验收、回滚和授权范围。`AD-*` 表示有证据支持的问题，`VFY-*` 表示还需验证的假设；待验证项的优先级表示补证紧迫度。

| 优先级 | 含义 |
|---|---|
| P0 | 有可信证据表明重大破坏正在发生或迫近，优先提出需批准的止损方案 |
| P1 | 关键正确性缺口，或持续阻塞正常交付 |
| P2 | 有证据的重复探索、上下文浪费或其他效率损失 |
| P3 | 低收益整理或可选便利，可以暂不处理 |

不设会掩盖单点风险的总健康分。没有发现问题时，看板可以为空。

## 快速安装

在本仓库的本地副本中运行：

```sh
python3 tools/package.py --check
python3 tools/package.py
```

这两个维护命令离线校验并生成安装包，不会安装 Skill，也不会运行被审计项目。需要 Python 3.9+；Skill 本身不依赖脚本。输出位于 `dist/`，已有同名 ZIP 时拒绝覆盖，可用 `--output <新目录>` 更换目标。

| 客户端 | 安装包 | 将完整 `agent-doctor/` 目录复制到 | 对话中调用 |
|---|---|---|---|
| Claude Code | `agent-doctor-claude-code-v1.2.0.zip` | `.claude/skills/agent-doctor/` | `/agent-doctor` |
| Codex | `agent-doctor-portable-v1.2.0.zip` | `.agents/skills/agent-doctor/` | `$agent-doctor` |
| OpenCode | `agent-doctor-portable-v1.2.0.zip` | `.opencode/skills/agent-doctor/` | `/agent-doctor`，需支持包内 metadata |

每个客户端选一处安装，不要只复制 `SKILL.md`。两个版本共用正文与参考规则；通用版仅移除 Claude Code 专用的 `disable-model-invocation` 字段。全局路径与触发策略见 [平台说明](references/platforms.md)。

## 22 项体检内容

先还原上下文来源及加载链，再建立检查账本，按风险和你的关注点深入。每项最终标为：**已证实问题、样本内未见问题、未知、不适用或未检查**。

| 维度 | 检查项 | 重点回答 |
|---|---|---|
| [上下文与工具](references/context-and-tools.md) | C01 effort；C02 Skill 体积；C06 工具输出；C13 全局指令；C14 仓库导航；G02 配置生效 | 当前任务实际加载了什么？信息是否有效？配置是否真正起作用？ |
| [工作流与决策](references/workflow-and-decisions.md) | C03 开工对齐；C04 过度对齐；C08 会话复盘；C09 人工审查；C10 原型验证；C12 自主工作边界；C15 共享术语；C17 交付策略；C18 决策验证 | 目标与验收是否清楚？哪些往返是必要决策，哪些可以减少？ |
| [验证与架构](references/verification-and-architecture.md) | C05 自动检查；C07 自动审查；C11 完成自证；C16 测试架构；G04 隔离与恢复 | 检查能否拦住错误？Agent 能否取得适当的完成证据？ |
| [安全与范围](references/safety-and-scope.md) | G01 权限与副作用；G03 敏感信息与外发 | 只读边界是否有实际保障？工具或配置是否带来越界风险？ |

覆盖 22 项不代表读遍每个文件。大仓库按关键模块取样，报告会列明没有检查的范围。

## 从体检到复查

### 1. 首次体检

在客户端中显式调用 Skill，然后说明范围和重点。例如在 Claude Code 或支持相应 metadata 的 OpenCode 中：

```text
/agent-doctor
体检当前项目及已授权的 agent 配置，重点看上下文消耗、工具输出和自动验证。
没有历史会话也继续做静态检查。先给上下文组成清单和加载链，再给整改看板、证据与可批准的方案。
```

Codex 使用 `$agent-doctor`。这些是对话指令，不是终端命令。只读与费用限制已内置，无需每次复述长篇禁令。

**即使当前宿主没有上下文统计，也要产出逐类结构清单和可追溯的加载路径/未知路径。** 默认使用 `audit` 模式。“重点看工具输出”会调整检查顺序，不会悄悄删掉其他维度；明确只检查某一范围时，其他项记录为本轮未检查。历史记录仅限当前可见会话及你授权的当前项目记录，不据静态配置推断日常习惯。

### 2. 批准方案，取得执行交接单

```text
批准这份报告中的 AD-001，按卡片列出的文件、修改动作、验证方式和副作用范围
生成执行交接单，其余暂不处理。保留已有未提交改动，不新增模型调用，不接触生产，
不提交或推送。
```

有边界明确的计划时，用自然语言确认即可，不需要固定口令或重复批准。批准保存报告只覆盖保存动作。**Agent Doctor 不执行整改**；你把交接单交给独立执行会话，再按获批范围实施。

### 3. 整改后复查

```text
/agent-doctor
复查上次报告中的 AD-001。旧报告和当前改动已提供，核对原问题与验收证据。
```

“复查上次问题”“核对整改”会映射为 `recheck`，明确指定模式则以你的指令为准。仅附旧报告不会自动切换模式。缺少旧报告时，先核对当前可见证据并说明基线缺口，不编造旧编号或关闭结论。

复查保留原问题 ID，区分“静态修改已出现”和“已有匹配的验收证据”。不会为了补证自行运行测试，也不会自动关闭 Issue 或看板任务。

## 为什么这些结论值得核对

**先找证据，再下判断。** 配置文件存在，不等于本次会话已加载；有测试脚本，不等于检查能阻断错误。每条发现都要有真实定位，并检查反证与替代解释。

**不把经验法则变成教条。** 高 effort、长参考文档、必要的人工审查都可能合理。删规则或测试之前，必须弄清它保护什么；无法排除独立用途时，先验证，不直接建议删除。已有机制能修好，就优先修好，而不是再装一套工具。

## 读取预算

项目证据与 Skill 自身规则分别计量，避免混淆取证覆盖与方法说明的开销；内部规则仍然占用上下文，并非免费。

| 类别 | 默认读取上限 | 内容 |
|---|---|---|
| 项目取证 | 60 次 / 60,000 字符 | 项目、配置、授权历史与其他被审计材料 |
| 内部规则 | 20 次 / 20,000 字符 | 当前调用的 Agent Doctor 入口与内部参考 |
| 合计 | 80 次 / 80,000 字符 | 两类相加；另受用户或宿主更紧的总限制约束 |

单次正文约 200 行，先定位章节再读取，复用已载入内容。任一适用上限到达就停止相应读取并披露缺口；无法精确计量时说明估算。数字是可调整的取样预算，不是性能保证或 API 账单。完整规则见 [安全与范围](references/safety-and-scope.md)。

## 安全边界

体检只读取授权材料、分析已有证据并在对话中给出方案。运行项目测试、构建、诊断命令、写文件、同步外部任务、安装依赖都留给单独获批的执行阶段；审计不会增开模型或子代理、读取凭据或访问生产系统。

**Prompt 不是沙箱。** 显式调用设置控制何时加载，不隔离写入。实际保护依赖宿主权限与工具约束；发现有写入副作用的读取路径时，停止该路径并寻找安全替代。已授权且契约明确的原生只读操作可直接进行，无需反复确认。
